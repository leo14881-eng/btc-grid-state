## Confirmed defects and minimum repairs

1. Monitor retained close price but discarded source timestamp. It could label
   an old three-day-window price as newly observed and use it for profit protection.
   Retain source `price_asof`; reject nonfinite/nonpositive prices, invalid or
   future timestamps, prior NY session dates, and 5m bars older than 35 minutes.
   The 35-minute data tolerance consists of the existing 20-minute SIP request
   delay, one 5m bar and 10 minutes of scheduling/transport tolerance. It is a
   data admissibility limit, not a V3 trading/profit threshold. The opening
   period may deliberately have no admissible delayed bar yet.
2. Main could reuse cached historical daily bars after missing or failed refresh.
   Preserve daily source time and require a current NY-date bar returned by a
   successful refresh before evaluating it for entry/lifecycle actions. Daily
   bars remain the frozen Main strategy's input; this does not turn Main into
   a realtime execution engine or prove intraday halt detection for all symbols.
3. Missing quotes skipped position updates but left old P&L without validity
   context. Preserve last-known numeric fields, tranches, extrema, lifecycle
   state, ledger and closed history; add separate quote/valuation status.
   Publish valid-subset P&L and return null for total current unrealized P&L
   whenever any position is unvalued. Realized historical statistics remain
   unchanged. Persistence arithmetic audit explicitly labels its old sums as
   LAST_KNOWN_PRICES_ARITHMETIC_ONLY and reports valuation coverage separately.
4. Add one verified effective-dated QRVO security event. Its block overrides
   a seemingly valid provider price and applies from the first halted regular
   session. No BUY/ADD/SELL, ledger removal, forced loss exit, SWKS conversion,
   or invented corporate-action proceeds occur automatically.

The existing QRVO BUY remains visible as historical paper evidence pending
corporate-action/invalid-fill reconciliation. This repair neither validates it
nor silently erases or reclassifies it. No frozen V3 score, fee, tranche,
profit-protection or recovery parameter is modified. No real-order capability
is added. General asset-status polling and a corporate-action accounting engine
are outside this minimum repair.

## Server acceptance remains open

The connected read-only server scheduler shows natural stock-shadow-monitor
triggers, stock-shadow-main hourly trigger, and replay timer. It does not expose
stock service details through its service-state subset. Actual reads of
`stock-shadow-monitor.service` logs and the stock runtime path were rejected by
the connector allowlist (Unapproved service / Path not approved).
Only Hunter/Sentinel deployment detail is exposed; it cannot establish the
stock checkout version. No deployment/write tool is available. This repair
has not been merged, deployed, or verified by a post-repair natural timer run.

After authorized deployment, accept only when:

- A natural Main and an in-session natural Monitor run record source SHA
  containing this repair, with matching run_id, generation/epoch and hashes
  read back from GitHub main. A closed-session skip is not the in-session test.
- QRVO reports CORPORATE_ACTION_HALTED, quote_actions_allowed=false and
  UNAVAILABLE_LAST_KNOWN_ONLY; raw missing_symbols remains separate from
  invalid_quotes. Its tranches, ledger, extrema and last-known numeric fields
  remain unchanged, with no synthetic SWKS position or event.
- A missing/stale quote produces no ADD/SELL and is excluded from current
  valuation; total unrealized P&L is null while coverage is partial.
- Restored admissible quotes resume ordinary V3 processing. Missing/future
  timestamps never acquire the processing timestamp as their source time.
- Existing Single Writer, CAS, idempotency and SHADOW ONLY guards still pass.

Do not equate PR merge, a SUCCESS wrapper, a closed-session run, or Hunter's
own deployment state with completed stock-server acceptance.
